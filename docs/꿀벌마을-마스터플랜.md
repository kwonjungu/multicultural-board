# 🐝 꿀벌 마을 (Bee Village) 마스터플랜

> 칭찬 꿀벌집을 "스티커 받고 끝"에서 **끝나지 않는 육성 서사**로 확장하는 총괄 기획.
> V1(코스메틱 40종 + 로열 마일스톤)은 2026-07 구현 완료. V2/V3 은 로드맵.
> 기존 `코스메틱-확장계획.md` 는 이 문서로 통합·대체됨.

## 1. 비전

- **한 문장**: 칭찬 스티커가 쌓일수록 나의 꿀벌이 자라고, 여왕벌이 된 뒤에도
  "로열 마일스톤"으로 계속 꾸밈이 열리며, 최종적으로 학급 전체가 하나의
  꿀벌 마을을 함께 가꾼다.
- **연구대회 4키워드 매핑**: 포용성(모든 학생의 벌이 전시장에 공존) ·
  학생주도(꾸미기 선택권) · 깊이 있는 학습(칭찬 준거 6종과 연결) ·
  디지털소양(자기 아바타 관리).
- **설계 원칙**
  1. **박탈 금지** — 해금은 누적만 있고 강등은 없다 (시즌 리셋 예외, §7).
  2. **조합 폭발 금지** — 신규 카테고리는 전부 런타임 오버레이. 사전 합성본이
     필요한 모자(hat)는 7종에서 동결 (CLAUDE.md 가드레일).
  3. **미리보기 = 실제 화면** — 렌더는 `CharacterComposite.tsx` 한 곳에만.

## 2. 진행 곡선 (스티커 개수 = 단일 축)

교사 칭찬 페이스를 주 1~2개로 가정하면: 여왕벌(15) ≈ 학기 중반,
전설의 여왕(30) ≈ 학기말 — 1년 운영에 맞는 곡선.

| 스티커 | 단계 | 열리는 것 |

| 0 | 🥚 알 | classic 스킨 |
| 2 | 🐛 애벌레 | 스킨 orange·green |
| 4 | 🛡 번데기 | 스킨 sky·pink·purple / 모자 top / 배경 4종 / 안경·목도리 |
| 8 | 🐝 벌 | 모자 cap·party / 오라 3종 / 펫 dog / 꿀단지·책 / 목걸이 |
| 15 | 👑 여왕벌 | 왕관 4종 / 왕좌 배경 / 로열 오라 / 펫 3종 / 트로피 gold·star / 망토 / 깃발 |

## 5. V2 — 꿀벌 마을 (칭찬판 **별도 탭** 게임) — 다음 단계

> 2026-07-13 사용자 방향 확정: 꿀벌 마을은 "스티커 꾸미기의 확장 화면"이
> 아니라 **PraiseHive 안의 별도 탭으로 들어가는 게임**이다. 스티커/꾸미기
> 축과 연계되되, 자체 게임 루프와 재화를 가진다.

- **진입**: PraiseHive 탭줄에 "🏡 꿀벌 마을" 탭 신설 (나의 꿀벌집·전시장과 병렬).
- **마을 맵**: 육각형 벌집 플롯 그리드(hex 타일링 가드레일 준수 — 반올림 금지).
  학생당 자기 집 1채, 내 벌은 코스메틱 착용 상태 그대로 등장(CharacterComposite 재사용).
- **게임 루프 (자체 재화 🍯 꿀)**
  1. **꿀 이슬 줍기** — 매일 첫 방문 보너스 (일 1회, `runTransaction` 원자화 가드레일).
  2. **내 집 가꾸기** — 마을 전용 데코(정원·지붕·문패 등)를 꿀로 구매/배치.
     스티커 해금 축과 독립인 "노력 재화" 축 → 스티커가 적은 학생도 마을에선 성취 가능(포용성).
  3. **친구 집 방문 + 물주기** — 하루 1회, 친구 정원 성장 게이지 기여 (상호 칭찬 문화).
  4. **마을 공동 시설** — 학급 스티커 합계로 분수대→꽃시계→축제 해금 (`stickers/goal` 연계).
- **스티커 연계**: 스티커 1개 획득 = 꿀 +5 같은 환전 보너스 (칭찬이 마을에서도 이득).
- **데이터**: `rooms/{}/village/{clientId}` = { honey, garden, house, lastDew: "YYYY-MM-DD", watered: {날짜: [friend...]} } — 신규 1노드.
- **에셋 정책**: 1차는 이모지+CSS+기존 스티커 재활용으로 무에셋 구현, 반응 좋으면 나노바나나 배치로 데코 에셋 웨이브 추가.
- V3(3D)는 마을에서 자기 집 클릭 → 3D 육성 룸으로 이어지는 구조.

## 6. V3 — 3D 꿀벌 육성 시뮬레이션 — 총괄 설계

> 이미 three.js 가 의존성에 있음 (`MulticulturalGlobe`, ~600KB, next/dynamic).
> 같은 패턴(지연 로드)으로 메인 번들에 영향 없이 도입 가능.

### 6.1 컨셉
- "나의 꿀벌 방": 학생이 자기 벌을 3D 로 만나는 개인 공간. 칭찬판의 성장
  상태·코스메틱이 그대로 3D 에 반영 (데이터 소스는 기존 노드, 신규 쓰기 최소).
- 상호작용 루프: ① 쓰다듬기(탭 → 애니메이션+하트) ② 꿀 주기(일 1회,
  `runTransaction` 원자화 — 가드레일 준수) ③ 산책(꽃밭 카메라 궤도).

### 6.2 기술 설계
- **모델**: 스테이지 5종 × 1 GLB (저폴리, 본 2~3개 스켈레톤). 코스메틱은
  본에 부착하는 방식 — 2D 처럼 조합 폭발 없음. 에셋은 Meshy/Tripo 류
  text-to-3D 로 초안 → Blender 정리.
- **렌더**: react-three-fiber 대신 기존 Globe 와 동일한 바닐라 three.js
  패턴 유지 (의존성 추가 최소화). `next/dynamic` + 뷰포트 진입 시 로드.
- **저사양 가드**: 교실 태블릿 기준 — 폴리 예산 총 15k, 그림자 OFF,
  pixelRatio 캡 1.5, 60fps 미달 시 30fps 스로틀.
- **데이터**: 읽기 = stickers/individual + cosmetics (기존). 쓰기 =
  `rooms/{}/village/{clientId}` { lastFeed: "YYYY-MM-DD", affection: n } 1노드만 신규.

### 6.3 단계별 마일스톤
1. **V3.0 PoC**: bee 스테이지 1종 GLB + 쓰다듬기 반응 (반나절~1일)
2. **V3.1**: 5스테이지 + 스킨(머티리얼 틴트) + 모자 부착 (2~3일)
3. **V3.2**: 꿀 주기 일일 보상 → affection 이 벌 애니메이션 풍부도에 반영
4. **V3.3**: 마을 광장(V2)과 통합 — 친구 벌 방문

## 7. 운영 정책 / 열린 결정

- **시즌 리셋과 해금**: `resetSeason()` 은 스티커를 비우고 코스메틱은 보존.
  → 리셋 후 count 가 0 이 되므로 **착용 중인 아이템은 유지되지만 픽커에서는
  다시 잠긴다** (기존 스테이지 방식과 동일한 동작). 연간 누적 해금을 원하면
  `stickers/lifetime/{clientId}` 누적 카운터 신설이 필요 — V2 백로그.
- **모자 신규는 동결**: hat-ribbon.png 에셋이 남아 있으나 합성본 25장이
  필요해 보류. 오버레이 폴백 품질이 확보되면 재검토.
- **에셋 미도착 아이템**: 픽커 타일이 404 시 이모지 폴백(🦊🦉💎🌌💠)으로
  표시되므로 코드 먼저 배포해도 UI 가 깨지지 않는다.
