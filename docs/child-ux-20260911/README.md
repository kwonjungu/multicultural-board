# 꿀벌 교실: 아동 친화 상용 품질 개편 설계서

작성일: 2026-09-11 · 대상: kwonjungu/multicultural-board · 기준 커밋: `ee898b008d51415aa94640341287a9720567da68`

이 패키지는 Claude Opus가 총괄하고 여러 구현 에이전트가 병렬 실행할 수 있는 실행 설계다. 낮은 성능 모델에는 파일 범위가 작은 작업만 맡기고, 계약·독립 테스트·시각 검수로 결과를 제한한다. 모델 능력이나 프롬프트만으로 상용 품질을 보장하지 않는다.

## 1. 결론과 범위

디자인 방향은 **따뜻한 꿀벌 교실**이다. 아이가 읽을 글자는 크고 차분하게, 눌러야 할 곳은 분명하게, 꿀벌은 행동을 돕는 안내자로 사용한다. 화면마다 무지개·그림자·입체 오브젝트를 늘리는 방식은 피한다. 핵심은 읽기, 선택, 표현, 친구의 말 이해하기다.

우선순위는 P0 게임 오류 및 합성 좌표 계약 → P1 시작/허브/소통창 → P1 칭찬집 → P2 3D 고도화다. 공통 토큰이 확정된 뒤 시작 UI를 첫 번째 시각 구현물로 완성한다. 모든 화면을 일괄 재작성하지 않고 기존 기능과 데이터 계약을 유지한다.

ART-01~04는 코드로 확인한 구조적 원인 후보다. 각 조합의 실제 어긋남 크기는 측정 전이며, 모든 자산이 나쁘다는 뜻은 아니다. GAME-02/03은 재현/제품 정책 확인이 필요한 위험 항목이며 확정 장애 건수에 넣지 않는다. 이미 구현된 3D DPR 상한, sRGB 텍스처, dispose, 2D 폴백은 유지·검증한다.

추가 자산 실측: 알 360×418px, 번데기 361×524px, 벌 399×399px, 여왕벌 356×356px다. 320px 정사각형에 contain할 때 알의 좌우 여백은 각각 22.20px, 번데기는 49.77px다. 이 여백을 제외한 좌표 변환이 필요하다. 이는 실제 소품 접점 오차를 측정한 수치는 아니며, 근거 원본 크기·알파 경계·SHA는 `asset-evidence.json`에 기록했다. 기본 벌 원본도 직접 열어 실루엣을 확인했으나 실제 조합 전체의 시각 승인은 아직 하지 않았다.

## 3. 아이 기준 사용 원칙

초등 1~3학년 및 한국어 초기 학습자를 기본 설계 대상으로 가정한다. 4~6학년은 큰 글씨를 유지하되 과한 유아 표현을 줄인 ‘차분하게’ 모드를 제공한다. 학년/국적을 추론해 자동 적용하지 않는다.

1. 한 화면에는 주된 질문 하나와 가장 중요한 버튼 하나를 둔다.
2. 아이콘에 항상 짧은 글자 라벨을 붙인다. ‘PLAY’, 언어 코드, 이모지만으로 안내하지 않는다.
3. 읽기 부담을 낮추기 위해 듣기·그림·말하기를 제공하되 자동 음성 재생은 하지 않는다.
4. 언어는 자국어 이름으로 선택한다. 국기/건축물은 보조 장식이며 국적 선택으로 오해시키지 않는다.
5. 오류는 아이 탓으로 쓰지 않는다. ‘연결이 잠깐 끊겼어요. 쓴 글은 남아 있어요.’처럼 현재 상태와 할 일을 말한다.
6. 친구와의 점수·보상 순위를 기본 노출하지 않는다. 개인 성장과 구체적 행동을 칭찬한다.
7. 교사용 관리 도구와 아이의 일상 행동을 시각적으로 분리한다. UI 숨김과 서버 권한 검증은 별개다.

## 4. 공통 디자인 시스템 — 작업 A

### 4.1 숫자로 고정할 규격

| 토큰 | 기본 | 큰 글씨 | 용도 |
|---|---:|---:|---|
| body | 1.25rem (20px) | 1.5rem (24px) | 글·댓글·설명 |
| body-emphasis | 1.5rem | 1.75rem | 문제·짧은 안내 |
| label | 1.125rem (18px) | 1.375rem | 버튼·탭 |
| secondary | 1rem (16px) | 1.125rem | 시간·상태; 필수 지시를 여기에 넣지 않음 |
| title | clamp(1.75rem, 1.5rem + 1vw, 2.25rem) | 기본의 1.2배 | 화면 제목 |
| reading line-height | 1.65 | 1.7 | 다국어 발음기호/결합문자 잘림 방지 |
| control-min | 56×56 CSS px | min-height 64px | 아이 조작 영역; 글 길면 세로 확장 |

| control gap | 8px 이상, 권장 12px | 동일 | 오터치 방지 |
| surface radius | 20px, 큰 패널 28px | 동일 | 카드·모달 |
| spacing | 4/8/12/16/24/32/48px | 동일 | 4px 배수 |

root 글꼴은 사용자의 브라우저 기본값을 존중한다. 표의 px는 기본 16px 환경 예시다. transform:scale이나 body zoom으로 전체 확대하지 않는다. 기존 글자 크기 설정이 있으면 새 토큰의 단일 설정으로 통합하고 이중 배율 적용을 막는다. inline px를 그대로 둔 채 루트만 키우는 작업은 불합격이다.

### 4.2 색·형태·동작

배경 `#FFF9ED`, 표면 `#FFFFFF`, 기본 글자 `#29251F`, 보조 글자 `#63574A`, 주 동작 배경 `#FFD35C` + 글자 `#38280D`, 선택 테두리 `#895300`, 초점 `#215FCC`, 성공 `#146B49`, 오류 `#B3261E`를 초기 후보로 한다. 실제 조합별 대비를 자동 계산해 기준 미달이면 조정한다. 흰색 글자+밝은 노랑 버튼은 사용하지 않는다.

한 카드에는 색 포인트 1개, 그림자 1개를 기본으로 한다. 큰 면적은 무채색/크림으로 안정시키고 민트·라벤더·살구색은 분류 힌트에만 사용한다. 본문 뒤에 패턴·이미지를 배치하지 않는다. 폰트는 본문 Pretendard/Noto 계열, 제목 장식 글꼴은 한 종류만 사용하고 언어별 fallback을 둔다.

눌림 100ms, 상태 전환 180ms, 축하 600ms 이내를 초기값으로 한다. reduced-motion에서는 배경 비행·흔들림·자동 카메라 이동을 끄고 즉시 상태 표시한다. 캐릭터를 쉬지 않고 다섯 마리씩 화면에 날리는 효과는 기본 화면에서 정적인 1마리 안내자로 축소한다.

### 4.3 접근성 계약

일반 텍스트 대비 4.5:1, 큰 텍스트 3:1, 의미 있는 비텍스트 UI 3:1을 확인한다. 200% 확대 시 정보/기능 손실을 허용하지 않는다. WCAG 2.2 AA 최소 타깃 규정과 본 프로젝트의 56px 아동용 목표는 다르다. 56px는 제품 기준이며 WCAG 필수 수치라고 설명하지 않는다. 근거: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [200% 텍스트 확대](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html).

키보드 초점은 3px 외곽선, 모달 열기/닫기 시 초점 이동·복귀, Escape 처리, 제목 연결을 갖춘다. aria-live는 결과/오류에 제한하고 매초 타이머나 스트리밍 토큰을 읽지 않는다. 힌디어·태국어 등의 글자 높이, 일본어 후리가나, 아랍어 RTL을 테스트한다. 방향 속성은 사용자 언어 기반 dir, 혼합 이름은 bdi로 처리한다.

## 5. 시작 화면과 홈 허브 — 작업 B

### 5.1 / 진입과 /1111 직접 입장

루트에서는 ‘우리 교실에 들어가요’ + 교실 번호 입력 + ‘들어가기’만 우선 노출한다. `/1111`처럼 방 번호가 이미 주어진 경우 재입력을 요구하지 않는다. 방 없음/연결 실패/로딩을 분리하며, 실제 방 설정을 받기 전에 명렬표나 임의 교사 권한을 표시하지 않는다.

입장 단계는 ‘편한 말을 골라요 → 내 이름을 골라요 → 우리 교실’이 학생의 기본 흐름이다. 기존 role 선택은 학생 경로의 기본 선택으로 정리하고, ‘선생님 입장’은 별도 보조 링크로 제공한다. 교사 PIN 및 권한 검증의 기존 계약은 별도 보안 검토 없이 제거하지 않는다. 명렬표 선택 모드는 유지하고 자유 입력 허용은 방 설정을 따른다.

| 상태 | 표시/행동 | 인수 조건 |
|---|---|---|
| 언어 선택 | 자국어 이름, 인사 한 줄, 듣기 버튼; 선택은 체크+테두리 | 색상 없이도 선택 인지 |
| 이름 선택 | 큰 이름 버튼; 긴 이름 2줄; 본인 재확인 | 40명도 세로 탐색, 가로 잘림 없음 |
| 입력형 | 이름 label, placeholder 외 안내, Enter 지원 | 빈 이름·공백만으로 입장 불가 |
| 처리 중 | 버튼 ‘들어가는 중…’, 반복 요청 잠금 | 빠르게 5회 눌러도 1회 처리 |
| 실패 | 원인에 맞는 쉬운 안내와 재시도 | 언어/이름 선택 유지 |
| 다시 방문 | 저장 상태 유효성 확인 후 이어가기 | 다른 방의 이름/언어가 섞이지 않음 |

모바일 360px: 좌우 16px, 상단 브랜드 48px, 안내 벌 72px, 제목, 단계, 입력 영역, 하단 CTA 순서다. 키보드가 열리면 장식 영역을 줄이고 입력/CTA가 스크롤로 보이게 한다. 100vh 고정+overflow:hidden으로 콘텐츠를 잠그지 않는다. 큰 화면 1024px 이상에서는 환영 일러스트 40%, 입장 패널 60%, 패널 최대 560px로 한다. 태블릿 가로에서도 콘텐츠 높이에 따라 자연 스크롤한다.

### 5.2 홈 허브

벌집 육각형은 브랜드 장식과 칭찬 표시로 유지하되 주요 탐색은 큰 직사각 카드로 만든다. ‘이야기 나누기’, ‘그림책 읽기’, ‘단어 배우기’, ‘나의 꿀벌’, ‘친구랑 놀기’의 5개 활동을 원래 라우팅에 매핑한다. 교사가 진행 중인 수업이 있으면 상단 ‘지금 함께할 활동’ 카드 하나를 강조한다. 기존 화이트보드/그림책 세션 우선순위와 퀘스트 이동을 회귀 검증한다.

360px에서는 1열, 600~1023px에서는 2열, 넓은 화면은 3열을 기본으로 한다. 카드 최소 높이 112px, 제목 22~24px, 아이콘 56px, 설명 한 문장. 큰 글씨/긴 번역에서는 자동 높이를 사용한다. 계정·언어·글자 크기·소리는 일관된 상단 설정 영역으로 둔다. 로그아웃은 실수하기 쉬운 아이콘 단독 대신 라벨 있는 메뉴 항목으로 둔다.

## 6. 꿀벌 소통창 — 작업 C

### 6.1 아이의 과제 순서

‘오늘 무엇을 이야기할까?’를 먼저 보여주고, 주제 선택 → 친구 글 읽기/듣기 → 내 이야기 올리기 → 답장하기 순서로 설계한다. 많은 컬럼을 옆으로 밀어야 하는 보드를 모바일 기본 화면으로 삼지 않는다.

모바일 상단: 뒤로/소통창/설정 → 오늘 주제 안내 → 주제 선택 탭(또는 선택 버튼) → 현재 주제 카드 1열 → ‘내 이야기 올리기’ 하단 버튼. 태블릿도 현재 주제 중심 보기, 데스크톱 교사에게는 기존 전체 컬럼 보기 옵션을 유지한다. 컬럼 데이터/정렬/추가·삭제 기능은 그대로 연결한다. 학생 기본 화면에는 관리 아이콘을 노출하지 않는다.

### 6.2 읽기 카드 규격

카드 폭은 모바일 가용 폭 전체, 읽기 영역 최대 42ch. 좌우 여백 20px, 본문 20~24px/1.65, 작성자 18px, 시간 16px. 정보 순서는 작성자 → 그림/사진(있는 경우) → 내 언어 본문 → 원문 보기 → 듣기·답장. 내 언어 번역을 기본으로 하고 한국어 학습 보기에서는 한국어+내 언어를 명시적으로 선택할 수 있다. 모든 언어를 동시에 쌓지 않는다.

‘번역 중’, ‘번역을 못 불러왔어요’, ‘원문 보기’를 별도 상태로 제공한다. 번역 실패를 빈 카드로 만들지 않는다. 긴 글은 줄수 제한으로 삭제하지 않고 ‘더 읽기’를 제공한다. 듣기 버튼은 대상 언어/본문과 연결하고 재생 중 ‘멈추기’로 전환한다. 카드 간 이동/모달 종료 때 기존 음성을 정리한다.

반응은 ‘고마워’, ‘나도 그래’, ‘멋진 생각’ 같은 의미 있는 선택지로 시작한다. 기존 좋아요 데이터는 호환 어댑터로 보존하고 반응 스키마 변경은 별도 작업으로 분리한다. 친구별 인기 순위나 반응 경쟁을 기본으로 노출하지 않는다. 빈 주제에는 ‘오늘 좋아했던 일을 하나 들려줘’라는 예시와 글쓰기 버튼 하나를 제공한다.

### 6.3 작성 흐름

첫 선택은 ‘글로 쓰기’, ‘말로 하기’, ‘그림·사진’ 3가지이며 기존 녹음/그림/사진/활동지 기능은 내부 상세 선택으로 이어간다. 입력란에 ‘나는 오늘 ___해서 기뻤어’ 같은 문장 시작 힌트를 선택형으로 제공한다. 힌트를 원치 않으면 빈 글쓰기를 허용한다.

작성 → 미리보기 → 올리기 → 서버 확인 → 카드 이동의 상태를 명시한다. 네트워크 실패는 초안을 유지하고 재시도한다. 로컬 에코를 ‘서버 저장 완료’와 혼동하지 않는다. clientRequestId를 생성해 동일 재시도를 식별하고 중복 저장 방지는 서버/DB 저장 경계에서 보장한다. 교사 승인 모드에서는 ‘선생님이 확인하고 있어요’를 표시하며 공개 성공으로 오인시키지 않는다.

텍스트 조합 중 Enter/Ctrl+Enter를 전송으로 처리하지 않는다. 마이크 거부/미지원은 글쓰기로 바로 전환한다. 녹음 시간과 중지 버튼을 명확히 표시하고 백그라운드 녹음을 멈춘다. 모바일 safe-area와 visualViewport에서 입력·올리기 버튼이 가려지지 않아야 한다. 최소 360×640과 가로 844×390에서 확인한다.

### 6.4 꿀비 AI 튜터의 경계

소통창(PadletBoard)과 꿀비 튜터(TutorChat)를 같은 기능으로 혼동하지 않는다. 튜터는 보조 도움이고 친구에게 보내는 글은 명시적 올리기를 통해서만 공유한다. 튜터 패널은 제목·접기·닫기·20px 대화문·큰 입력창으로 구성한다. 생성 중 멈추기, 스트림 실패 재시도, 최신 요청 ID 검사, 닫기/unmount abort, IME 보호를 계약에 넣는다. 기존 SSE 및 안전성 후처리를 유지한다.

## 7. 칭찬 꿀벌집과 합성 오브젝트 — 작업 D

### 7.1 아이에게 보일 구성

상단에는 ‘친구의 말을 끝까지 들어줬구나!’처럼 실제 칭찬 이유, 중앙에는 내 꿀벌 240~320px, 아래에는 ‘꾸미기’와 ‘칭찬 모아보기’를 둔다. 스티커 수는 보조 정보다. 다음 단계는 ‘칭찬 2개를 더 모으면 새 모습이 나타나요’로 표현하되 기존 단계/해금 수치는 바꾸지 않는다. 전체 학생 전시는 작은 캐릭터와 이름으로 제공하며 점수 내림차순 기본 정렬은 피한다.

### 7.2 자산/좌표 계약 v2

현재 assets를 전부 새로 생성하기 전에 파일 크기·알파 bbox·종횡비·존재 조합을 inventory로 만든다. 원본 PNG를 보존하고 trim은 복제 출력 디렉터리에만 수행한다. 기존 trim 스크립트 재실행으로 패딩이 누적되지 않는지 해시를 확인한다.

`public/stickers/manifest-v2.json`의 항목은 assetId, version, sha256, file, sourceWidth, sourceHeight, alphaBounds, anchors(headTop, eyes, neck, leftGrip, rightGrip, ground), slots, compatibleStages, authoredView, lightDirection, approved를 가진다. 좌표는 **해당 파일의 최종 trim 캔버스 픽셀 좌표**로 통일한다. skin과 합성본도 원본과 실루엣이 다르면 별도 assetId를 가진다. `_doc` 같은 메타 문자열은 records 밖 meta 객체에 둔다.

컨테이너 W×H, 자산 w×h이면 `s=min(W/w,H/h)`, `ox=(W-w*s)/2`, `oy=(H-h*s)/2`. 앵커 (ax,ay)의 화면 좌표는 `(ox+ax*s, oy+ay*s)`다. 퍼센트가 필요하면 이 변환 후 계산한다. 액세서리 자체 접점 (gx,gy), 배율 q이면 왼쪽 위는 `(targetX-gx*q,targetY-gy*q)`다. 회전은 접점을 transform-origin으로 사용한다. 카메라/포즈가 다른 자산에 동일 수치를 복사하지 않는다.

예: 자산 400×800, 컨테이너 300×300이면 s=.375, ox=75, oy=0이다. 자산 x=100 앵커는 화면 x=112.5이며 단순 25%인 75px와 37.5px 차이가 난다. 이 예는 좌표 변환 단위 테스트의 고정 정답이다.

### 7.3 합성 경로와 레이어

순서: approved 동일 stage+skin+hat 완성 합성본 → 동일 stage+skin 원본+검증된 모자 오버레이 → 동일 stage+skin 원본(장식 준비 상태 표시) → 기본 stage 원본 → 최종 정적 placeholder. classic으로 바뀌는 경우는 해당 스킨 자체도 없을 때만 허용하고 개발 로그에 남긴다. manifest에 없는 조합을 404 탐색으로 알아내지 않는다. 네트워크 오류는 각 후보 1회, 모든 실패 후에는 안정된 placeholder로 끝낸다.

레이어는 background → environment shadow → cape-back → body-back → held-back → body/front-hand mask → hat/face accessory → held-front → aura 순서다. 실제 자산이 단일 body PNG라면 손 앞/뒤가 필요한 조합은 승인된 완성 합성본을 우선한다. 마스크가 없는 상태에서 물체를 임의로 전면에 붙여 ‘쥐고 있다’고 처리하지 않는다. 알/번데기처럼 손이 없는 단계는 held를 주변 소품으로 배치하거나 지원하지 않음을 manifest에 명시한다.

`CharacterRenderPlan`을 공통 순수 함수로 생성하고 PraiseHive, CosmeticPicker, BeeVillage에서 공유한다. Props는 stage/skin/hat/held/acc/backdrop/aura/size/reducedMotion이고 plan은 resolvedAssetId, layers, transforms, clipMasks, status를 반환한다. body+착용물은 단일 부모 그룹에서 부유하고, 배경/오라는 별도 환경 레이어다. 그림자는 장면 접지용 1개를 기본으로 하고 레이어마다 서로 다른 방향의 진한 그림자를 추가하지 않는다.

### 7.4 미술 방향과 승인

벌·모자·소품은 둥근 실루엣의 무광 점토 장난감 스타일, 동일 3/4 시점, 왼쪽 위의 넓고 부드러운 광원으로 통일한다. 실사 금속 왕관과 평면 만화 몸체를 섞지 않는다. 얼굴·눈·손을 가리지 않고 외곽선 두께와 재질의 광택을 맞춘다. 색/시점은 기존 대표 벌 1종을 골라 기준 이미지로 동결한 후 측정한다.

대표 승인판: bee+classic+glasses, bee+sky+cap+book, queen+pink+crown-honey+necklace, queen+classic+cape+flag, pupa+scarf, 모든 자산 실패. 흰색/크림/어두운 배경, 96/160/320px, 정지/부유 각각 비교한다. 지원 조합 전체는 자동 무결성 검사, 대표 조합은 시각 승인, 문제 발견 범주의 조합은 전수 검수한다. anchor 오차는 320px 렌더 기준 접점 3px 이내를 초기 목표로 한다. 의미적 자연스러움은 수치만으로 통과시키지 않는다.

신규 이미지 생성은 마지막 단계다. 저장소 CLAUDE.md의 이미지 생성 비용·모델·배치 제한을 준수한다. 이번 설계에는 유료 생성 실행을 포함하지 않는다.

## 8. 3D 업데이트 — 작업 E

### 8.1 결정: 안정적인 2.5D부터 완성

현재 Three.js+Sprite 구조를 유지한 2.5D 개선을 1차 출시한다. 2D 그림을 회전 가능한 실제 3D 모델처럼 설명하지 않는다. 그림 기반 건물은 카메라 이동 시 종이처럼 보일 수 있으므로 회전 범위와 건물 방향을 제한하고 고정 등각 보기 옵션을 기본으로 검토한다. OrbitControls 조작은 보조 기능이다.

장면: 잔디 바닥 → 길 → 공동 광장 → 각 학생 집 → 정원/울타리 → 벌 → 선택 강조. 집은 ground anchor로 바닥에 붙인다. 빌보드 중심을 ground로 착각해 반쯤 파묻거나 띄우지 않는다. 소프트 접지 그림자와 일관된 비율로 공간감을 만든다. depthWrite/alphaTest/renderOrder는 투명 오브젝트 겹침 테스트로 결정하며 무작정 전체 depthTest를 끄지 않는다.

뷰 구성: ‘내 집 찾기’ 64px 버튼, 확대/축소/전체 보기 56px, 학생 집 선택 시 DOM 정보 패널, 키보드로 탐색 가능한 ‘친구 목록 보기’를 제공한다. 터치 드래그와 탭은 이동 거리 임계값으로 구분하고, 페이지 세로 스크롤을 가로채지 않는 조작 영역을 설계한다. 학생 이름은 WebGL 텍스처만으로 제공하지 말고 선택 패널/목록의 DOM 이름으로도 읽을 수 있게 한다.

### 8.2 렌더·성능 계약

현재 DPR≤1.5, sRGB 텍스처, dispose를 유지한다. 데이터/카메라 변경 시 invalidate 방식, 문서 hidden 시 중지, reduced-motion 시 연속 애니메이션 없음. resize와 unmount 후 늦은 이미지 load callback은 disposed/generation token으로 무시하고 생성된 텍스처도 정리한다. 캐시 키는 asset version+plan hash로 하며 꾸미기 변경 때 오래된 텍스처가 적용되지 않게 한다.

초기 목표: 30명 장면에서 기준 Android 중급 태블릿 조작 중 p95 frame time≤33ms, 정지 5초 후 지속 rAF 없음, 20회 진입/퇴장 후 renderer.info의 geometry/texture가 기준으로 회복. Three와 마을 자산은 홈 초기 번들에서 지연 로드하고, 3D 준비 중 동일 데이터의 2D 지도를 보여준다. GPU/네트워크 편차 때문에 3D 준비 3초 초과 또는 context loss 시 2D를 유지해 활동을 계속할 수 있게 한다. 수치는 목표이며 현행 측정값이 아니다.

### 8.3 실제 3D는 2차 별도 게이트

필요 시 GLB 벌 1종과 집 1종으로 먼저 검증한다. 벌의 head/eye/hand 소켓과 모자·held rig를 표준화하고 실제 mesh/재질/라이트를 공유한다. 스프라이트용 퍼센트 앵커를 GLB에 재사용하지 않는다. GLB 렌더도 CharacterRenderPlan의 동일 슬롯 의미에 매핑한다. 캐릭터 전체 20k triangles 이하, texture 1024² 이하, 단일 scene 다운로드 추가 3MB 이하를 초기 예산으로 잡고 실측 조정한다. low-tier는 정적 2.5D로 돌아간다. 원본 Blender/GLB·라이선스·버전·검수판 없이 생성 이미지 파일만으로 실제 3D 완료를 선언하지 않는다.

색 공간은 [Three.js 공식 색 관리 문서](https://threejs.org/manual/en/color-management.html)를 기준으로 검증한다. 2D 이미지에 이미 구워진 조명과 실시간 조명을 중복 적용하지 않는다.

## 9. 소통의 게임 개선 — 작업 F

기억 카드는 이번에 상태 처리를 고쳤다. 언어 조합별 round를 새로 마운트하고, 짝 판정·시도 수를 reducer의 두 번째 카드 전이에서 한 번만 계산한다. effect는 카드 표시를 닫는 타이머만 관리하며 cleanup한다. 오래된 settle은 카드 쌍이 다르면 무시한다. 새 음성 전에 이전 음성을 멈추고 unmount 시 정리한다. UI lifecycle 자동 검증은 후속 하네스에 명시하며 순수 reducer 테스트와 구분한다.

게임 목록은 ‘듣고 찾기/함께 말하기/생각하며 놀기’의 선택형 필터와 오늘 추천 3개로 시작한다. 실제 목록은 GameRoom GAMES에서 추출하고 게임 수를 20개로 하드코딩하지 않는다. 각 게임에 인원·예상 시간·한 문장 규칙·연습 1문제를 제공한다. 시간 경쟁은 선택 가능하게 하고 오답에 화면 흔들림/큰 경고음 대신 ‘한 번 더 들어볼까?’를 사용한다.

공통 인터페이스는 기존 langA/langB를 유지하면서 sessionId, onMeaningfulAction, onComplete, onExit를 선택적으로 도입한다. 게임 진입/닫기만으로 보상을 주지 않도록 의미 있는 행동을 정의하되 현재 퀘스트 정책과 합의해 전환한다. 보상은 클라이언트 버튼 잠금만 믿지 않고 트랜잭션+안정적 eventId로 중복 방지한다.

## 10. 출시와 완료 정의

1. A 공통 계약 → B 시작 화면을 첫 시각 기준으로 승인한다.
2. B/C/D/F를 병렬 개발하고 D의 render plan 고정 후 E를 연결한다.
3. 테스트 방/로컬 fixture에서 통합한다. 운영 학생 명단·게시글을 테스트 fixture로 복제하지 않는다.
4. QA는 HARNESS의 필수 조건과 미검증 목록을 제출한다. 테스트 미실행을 통과로 간주하지 않는다.
5. 별도 미리보기 배포 후 교사와 아동 사용성 관찰을 거친다. 아동 5~8명은 초기 형성 평가 표본이며 전체 사용자 적합성을 통계적으로 증명하지 않는다. 읽기 수준/언어가 다른 아이를 포함한다.
6. 관찰 과제: 스스로 입장, 주제 찾기, 친구 글 듣기, 내 이야기 게시, 꾸미기 결과 확인, 게임 한 판. 목표는 핵심 과제별 80% 이상 무도움 성공과 심각한 막힘 0건. 실패 시 해당 단계 재설계한다. 음성·영상/실명 기록은 수집하지 않는 관찰 메모부터 사용한다.
7. 구현 전후 오류 수·번들·속도·스크린샷을 같은 환경에서 비교한다. 배포는 검증된 커밋만 대상으로 하고 이전 배포로 복귀할 수 있어야 한다. 데이터 마이그레이션은 이 UI 변경과 분리한다.

완료는 ‘예쁜 화면 캡처’가 아니라 입장→소통→칭찬→게임→복귀가 큰 글씨·다국어·실패 상황에서 끝까지 동작하는 상태다. 전체 디자인 구현과 운영 배포는 이 설계서 작성 결과에 포함되어 완료된 것으로 표시하지 않는다.
