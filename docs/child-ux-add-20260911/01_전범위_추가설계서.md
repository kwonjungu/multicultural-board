# 꿀벌 교실 전 범위 추가 설계

## 1. 이번 확장의 방향

‘화면마다 기능을 추가’하기보다 **아이가 스스로 고르고, 여러 방식으로 표현하고, 실수해도 계속 배우며, 기록이 안전하게 남는 교실**로 확장한다. 자유도는 개발자가 구현 방식을 선택할 자유와 아이가 학습·표현 방식을 선택할 자유를 모두 포함한다. 핵심 인수 조건과 데이터 안전성은 고정하고 미술 표현·레이아웃은 같은 목표 안에서 대안을 시험할 수 있게 한다.

검토 범위: 입장/홈, 소통창/AI 튜터, 그림책/독후 활동, 단어/발음/받아쓰기, 통역, 토론/화이트보드/그리기, 칭찬/퀘스트/마을, 교사 대시보드/명렬표, 다국어/공유 기기, 네트워크/권한/자산/성능.

자율성·관계·창의성·역량을 제품 평가에 포함하는 방향은 [UNICEF RITEC Design Toolbox](https://www.unicef.org/childrightsandbusiness/workstreams/responsible-technology/online-gaming/ritec-design-toolbox)를 참고했다. 다만 해당 프레임워크의 연구 연령과 본 앱 저학년 사용자는 같지 않으므로, 이 제안의 효과는 실제 교실에서 확인해야 한다. 표현 수단과 선택권을 제공하는 설계는 [CAST UDL Guidelines](https://udlguidelines.cast.org/)를 참고했다. 아래 수치·우선순위·화면 구성은 본 프로젝트에 대한 설계 판단이지 해당 기관의 의무 기준은 아니다.

## 4. P0: 먼저 고칠 데이터·녹음 계약

### X01~02. 이름은 표시값, 기록은 학습자 ID

새 LearnerProfile은 learnerId(UUID), displayName, rosterStatus(active/archived), createdAt, updatedAt, version을 가진다. 이름 변경은 displayName만 수정하며, 동명이인은 별도 learnerId를 가진다. 교사 UI에는 아이가 구별할 수 있는 개인 그림 표식을 보조로 제공한다. 국적·피부색으로 자동 구분하지 않는다.

명렬표 편집에서 ‘이름 고치기’, ‘이번 명렬표에서 보관하기’, ‘기록 완전 삭제’를 분리한다. 기본 제거는 보관이며 기록을 유지한다. 제거 예정 목록·영향 범위를 미리 보여주고 보관함에서 복원한다. 완전 삭제는 교사 관리의 별도 후속 경로이며 기본 편집 동작에 묶지 않는다.

마이그레이션: 기존 경로 읽기 inventory → 이름 키/learnerId 매핑 초안 → 동명이인·모호한 매핑은 교사 해결 → 백업 및 dry-run diff → 테스트 프로젝트에서 idempotent copy → 합계/콘텐츠 hash 비교 → 새 경로 읽기 전환. 기존 이름 경로는 즉시 삭제하지 않는다. 전환 중 쓰기는 한 권위 경로로 고정하고 양쪽 독립 쓰기를 피한다. rollback 때 새로 생긴 기록도 보존하는 역변환 계획을 먼저 작성한다.

인수: 이름 1회 변경 후 스티커·꾸미기·단어·녹음·학습 기록 동일; 동명이인 각각 독립; 보관/복원 후 기록 동일; 실패한 저장에 성공 안내 없음. 실제 운영 마이그레이션은 별도 검증 단계다.

### X03. 녹음은 화면 상태가 아닌 세션 자원

recordingSessionId, recorder instance, timeoutId, media tracks, pendingRequestId, objectURL을 한 세션으로 묶는다. 시작 전에 이전 timeout/트랙/오디오/URL 정리. 15초 제한 callback은 당시 rec와 sessionId를 캡처하고 최신 세션과 같을 때만 그 rec를 멈춘다. 예문 변경·닫기는 cancel 처리이며 onstop 이후 자동 STT를 시작하지 않도록 cancelled 상태를 검사한다. getUserMedia가 늦게 성공하면 세션이 무효인지 확인해 반환된 트랙을 즉시 멈춘다.

UI: ‘말해 보기 → 들어 보기 → 다시 말하기/저장’의 순서. STT 분석은 명확한 상태 표시와 취소를 제공한다. 브라우저별 실제 rec.mimeType을 Blob type과 업로드 metadata에 반영하고 오디오 형식을 고정 가정하지 않는다.

인수: t=0 녹음 A→t=2 중지→t=3 녹음 B→t=15에도 B는 지속, B 제한은 t=18. 닫은 뒤 녹음/타이머/자동 STT 0개. 권한 요청 후 화면 이동 시 늦게 받은 트랙 즉시 stop.

### X04~05. 보상은 ‘한 번’과 ‘끝까지’ 모두 보장

현재 claimed=true 선점 후 honey 지급 실패는 재시도만으로 회복하지 못할 수 있다. claim을 단순 불리언 대신 eventId, learnerId, questId, dayKey, status(pending/applied), amount, policyVersion으로 기록한다. 권위 서버에서 원자적으로 잔액과 지급 원장을 함께 변경하는 방식을 우선 설계한다. RTDB에서 공통 조상 transaction을 쓸 경우 범위/충돌/전송 비용을 검토한다. 광범위 transaction을 무조건 적용하지 않는다. 분산 단계가 남으면 각 단계의 applied event ledger와 재처리 worker가 필요하며 ‘exactly once’라는 명칭만 붙여 해결했다고 하지 않는다.

실패한 claim은 pending으로 보이고 재시도/재조정이 가능해야 한다. 같은 eventId의 두 요청은 지급 1회, 지급 도중 프로세스 종료 후 복구되어 누락 0회. XP도 보너스와 같은 지급 이벤트에 연결하고 일부만 성공하는 상태를 관리한다.

dayKey는 교실 timezone 설정으로 결정한다. dateKey를 목록 계산·구독·수령에 같은 값으로 전달하고 화면 복귀/자정에 재평가한다. UI에서 날짜가 달라졌으면 ‘새로운 하루가 시작됐어요’ 후 목록/구독을 함께 바꾼다. 완료 당시 dayKey를 보상 이벤트에 고정한다. 구독 cleanup은 해당 subscribe가 반환한 unsubscribe를 사용해 다른 구독에 영향을 주지 않도록 검증한다.

## 5. X06~09: 학습 자유도를 실제로 높이기

하트가 다 떨어져도 ‘힌트 보며 계속 연습하기’를 제공한다. 점수 도전 모드와 연습 모드를 분리하고, 연습 기록을 도전 점수/보상과 구별해 저장한다. ‘실패해서 쉴 수밖에 없음’ 대신 아이가 쉬기·연습하기를 고른다. 하트/XP 규칙은 UI 문구만 바꾸지 말고 lib/lms 및 결과 처리 계약을 함께 수정한다.

홈에는 교사 지정 필수 활동 1개와 아이 선택 활동 2개를 구분한다. 필수 수업을 우회하는 권한을 무조건 추가하지 않는다. 선택 과제에는 읽기·말하기·그림 같은 서로 다른 방식이 들어가며 같은 목표로 인정할 수 있는지는 교사가 설정한다. 퀘스트 이름도 ‘심부름’ 고정에서 교실별 ‘오늘의 탐험’ 등으로 조정 가능하게 한다.

오답은 정답만 보여주고 끝내지 않는다. 1차 ‘한 번 더 듣기’, 2차 그림/예문 힌트, 3차 함께 풀기, 나중에 다시 보기의 사다리를 둔다. 실패 횟수를 아이에게 크게 노출하지 않는다. 교사는 도움 없이 해결했는지/도움 후 해결했는지를 확인할 수 있으나 비교 순위로 쓰지 않는다.

포트폴리오는 ‘이번 주 내가 할 수 있게 된 것’ 3개와 아이가 고른 작품 1개를 보여준다. 정답률·XP 위주 대신 실제 문장·그림·발음 전후를 아이가 선택한다. 녹음 공개는 기본 비공개이며 스스로 선택/교사 설정을 거쳐 공유한다. 목표: 완료 후 아이가 배운 것을 한 문장 또는 그림으로 설명할 수 있는지 관찰한다.

## 6. X10~15: 그림책·발음·통역·토론·창작

그림책 집중 보기에서는 본문/그림/넘기기/듣기만 남긴다. 줄별 강조·문장 한 줄씩 보기·단어 뜻 열기·내 언어 보조를 선택 가능하게 한다. 생성된 글과 그림의 인물·장소·사건 일치를 출판 전 검수하고, 이미지 속 문자로 본문을 대체하지 않는다. 기존 캐릭터 참조/안전 후처리 경로를 유지한다.

독후 활동은 ‘정답 맞히기’ 외에 ‘나도 이런 적 있어’, ‘다른 끝을 그려 봐’, ‘친구에게 물어볼 말’을 제공한다. 답을 글/녹음/그림으로 제출할 수 있게 하고 동일 세션의 응답으로 묶는다. 시간 내 발언하지 못한 아이에게도 나중에 표현할 기회를 둔다.

발음은 STT 일치율을 정확한 발음 평가로 단정하지 않는다. ‘이렇게 들렸어요’ 원문, 모델 음성, 다시 말하기를 제공한다. 소음/마이크 문제와 학습자의 발음 문제를 구분하고 특정 억양을 틀린 인격적 특성처럼 평가하지 않는다. 자동 추천 피드백은 교사가 검토 가능한 자료로 남긴다.

통역 화면에는 화장실·도움·함께 놀기·잘 모르겠어요·다시 말해 주세요 같은 기본 문장 카드를 제공한다. 기기를 마주 보는 두 면 보기와 같은 방향 보기를 선택하게 한다. 말할 사람을 이름/라벨/방향으로 보여주고, 언어만으로 사람을 추정하지 않는다. 한 번에 재생 음성은 1개, 번역 원문도 함께 확인한다. 긴급 의료 판단을 대신하는 도구로 확장하지 않는다.

토론에는 ‘말하고 싶어요’, ‘조금 더 생각할래요’, ‘이번에는 들을래요’를 둔다. 패스가 불이익이 되지 않도록 하며 발언 순서는 교사 조정 가능. 타이머는 시간 압박보다 차례 예고로 사용한다. 말하기 참여만을 유일한 기여로 세지 않는다.

그리기는 공통 도구로 선 색/굵기, 지우개, undo/redo, 전체 지우기 복구를 통일한다. 기존 DrawBoard 기능을 재사용할 수 있는지 먼저 검토한다. 터치 취소/회전/resize에서 좌표와 그림을 보존하고 도형 선택→위치 선택 방식도 제공한다. 프레임·소품 에셋은 아이의 그림을 돋보이게 하는 선택형 도구이며 처음부터 캔버스를 채우지 않는다.

## 7. X16~23: 교사 운영·공용 기기·회복·권한

교사 운영 화면은 수업 시작, 오늘 활동, 참여 상태, 도움 요청, 승인 대기를 한 곳에 모은다. 단순 ‘접속함’을 ‘학습 중’으로 해석하지 않는다. 학생별 상태는 연결/최근 활동/제출 완료를 구분하고, 새로고침하지 않아도 최신성을 알 수 있게 한다. 화면 공개 시 학습 부진 순위나 사적 감정 응답이 자동 노출되지 않게 한다.

통합 확인함에는 게시 승인, 번역 실패, 녹음 재시도, 미지급 보상, 생성 콘텐츠 검수 등 조치가 필요한 항목만 모은다. 각각 해당 화면으로 이동하고 처리 후 상태가 갱신된다. 대시보드가 데이터를 새로 복제해 별도 진실을 만들지 말고 원본 상태의 view로 구성한다.

공용 태블릿은 ‘사용자 바꾸기’를 명시적으로 제공한다. 전환 시 오디오/녹음/구독/메모리 초안을 정리하고 localStorage/IndexedDB는 roomId+learnerId로 격리한다. 다른 아이에게 이전 아이의 초안·대화·작품이 보이지 않아야 한다. ‘이어하기’는 같은 학습자에게만 제안한다. PIN을 localStorage의 교사 불리언으로 대체하지 않는다.

전역 설정은 글자 크기, 소리, 움직임 줄이기, 집중 모드로 한정해 아이에게 이해 가능한 말로 표시한다. 동일 음성 서비스가 WebSpeech와 HTMLAudio를 함께 관리하고 새 재생 전 양쪽을 중지한다. 집중 모드는 배경 비행, 오라, 튜터 팝업, 보상 반복 애니메이션을 줄이며 기능은 유지한다.

비동기 작업은 idle/editing/queued/running/succeeded/failed/cancelled 상태를 공통 계약으로 정한다. ‘로컬에 남김’과 ‘서버 저장됨’을 구분하고 실제 저장 여부를 정확히 보여준다. 재시도 버튼은 새 게시물/보상 중복을 만들지 않는 requestId를 재사용한다. 긴 생성 작업은 진행 단계와 취소/나중에 확인을 제공한다. 취소했다고 서버 과금/처리까지 중지됐다고 단정하지 않는다.

콘텐츠 대장에는 contentId, lang, source, approvedBy, reviewedAt, license, assetId, version, textAlternative를 둔다. 국기·랜드마크·의상 하나로 한 나라/문화를 고정 설명하지 않는다. 단어 그림의 정답 모호성, 이미지 누락, 번역과 그림 불일치, 비슷한 보기 중 복수 정답을 교사가 신고/교정할 수 있게 한다. 다국어가 없는 메뉴는 한국어로 조용히 바꾸는 대신 지원 범위를 명시한다.

권한 경계는 현재 배포된 rules와 API를 따로 검사한다. 교사 PIN이 화면에서 보이는지, 학생이 isTeacher를 바꾸거나 API를 직접 호출해도 쓰기가 차단되는지 테스트 프로젝트에서 확인한다. 현재 코드만으로 운영 권한 취약성이 확인됐다고 단정하지 않는다. 권한 문제 발견 시 서버 세션/인증·방 멤버십 검사와 데이터 쓰기 규칙을 수정한다. UI 변경과 보안 마이그레이션의 롤백은 분리한다.

## 8. X24~29: 더 자유롭게 실험할 수 있는 확장

공동 정원은 친구별 기여량 순위 없이 전체의 작은 기여로 꽃/쉼터가 생기는 장면이다. 한 아이가 기여하지 않았다고 집단 목표를 방해한 것으로 표시하지 않는다. 결석 시 정원이 시들거나 연속 참여를 강요하지 않는다. 수업 활동과 연결된 1일 상한을 두고 반복 탭 수집을 유도하지 않는다.

개인 공간은 배경·좋아하는 색·별명/칭찬 문장·작품 전시를 선택하게 한다. 보상으로 잠긴 물건만 늘리지 말고 기본 꾸미기 선택지를 충분히 제공한다. 새 미술 스타일을 도입할 경우 기존 벌과의 호환 판을 승인한 뒤 전체 계열을 교체한다. 기존 1차 설계의 합성 render plan을 우회하지 않는다.

감정은 표정만으로 정답을 맞히게 하지 않는다. ‘여러 마음이 함께 있어’, ‘잘 모르겠어’, ‘말하고 싶지 않아’를 제공하고 맥락과 아이의 설명을 존중한다. 교사에게 자동 위험 등급이나 진단을 부여하는 기능으로 확장하지 않는다. 학급 공개/비공개 응답 범위를 분명하게 한다.

교사 꾸러미는 주제·그림책·단어·게임·성찰 질문을 묶은 복제 가능한 템플릿이다. 복제 시 원래 방의 학생 데이터/답변은 포함하지 않는다. 출처·수정일·지원 언어·준비물·예상 시간을 보여준다. 수업 운영 실패 시 이전 설정으로 돌아갈 수 있어야 한다.

저속 연결 모드는 텍스트+정적 그림+설치된 TTS 등 이미 가능한 기능부터 제공한다. 전체 offline 서비스워커를 즉시 도입하지 않는다. 자산/버전 캐시 무효화·공용 기기 데이터 격리·보류 업로드 중복 방지가 준비된 뒤 확장한다. 오프라인 콘텐츠는 다운로드 완료된 범위만 사용 가능하다고 표시한다.

연습방은 가짜 이름/가짜 게시물로 입장·듣기·글쓰기·꾸미기를 연습하는 로컬 fixture다. 운영 방에 샘플을 쓰지 않는다. 아이는 언제든 건너뛰고 나중에 도움말에서 다시 연습한다. 작은 기능 도입마다 팝업 튜토리얼을 반복하지 않는다.

## 9. X30: 더 가볍고 운영 가능한 앱

1차 수정 후 빌드에서 room route First Load JS 535kB가 측정되었다. 이번에 새로 측정한 운영 지표가 아니다. 게임, PPT/문서 처리, 3D, 제작 도구를 실제 방문 시 로드하도록 import 경계를 조사한다. 지연 로딩 후에도 키보드 초점과 뒤로 이동을 보존한다. 기능 수가 늘어날수록 홈에서 모든 에셋을 preload하지 않는다.

오류 기록에는 기능/단계/에러 코드/버전/익명 requestId만 기본 수집하고 학생 글·음성·실명은 넣지 않는다. 특정 오류가 늘면 해당 기능을 안전한 fallback으로 전환할 수 있는 flag와 운영 안내를 마련한다. 자동 수집 도입은 데이터 항목/보관 기간/접근 권한을 먼저 정한다.

현재 설치 시 확인된 Next 14.2.5 보안 경고는 별도 의존성 업데이트 작업으로 다룬다. 정확한 목표 버전은 적용 시 공식 공지로 다시 확인하고 여기서 최신 번호를 추정하지 않는다. UI 개편의 완료 조건에 타입/빌드뿐 아니라 권한·저장·회복·장시간 안정성 검증을 넣는다.

## 10. 허용할 디자인 자유와 고정할 계약

자유롭게 시도: 홈 카드 배치 2안, 몰입 읽기 2안, 평면/부드러운 입체의 미술 기준판 2안, 공동 정원의 테마, 문장 시작 힌트의 문구. 각 안은 같은 fixture와 과제로 비교한다.

고정: 읽기 크기/터치 영역/대비, 학생 기록 보존, 요청 중복 방지, 접근성 이름, 언어 지원 범위의 정직한 표시, 녹음 종료, 기존 수업 라우팅 계약, 승인된 자산 일관성. 자유도를 이유로 이 기준을 지우지 않는다.

제품 성과는 체류시간 증가보다 무도움 과제 성공, 재시도 후 회복, 여러 표현 방식 사용, 교사의 준비 시간 감소로 판단한다. 형성 평가 5~8명과 교사 2명으로 시작하고 학년/읽기 수준/언어/입력 방식의 차이를 관찰한다. 작은 표본을 효과 입증 통계로 제시하지 않는다.
