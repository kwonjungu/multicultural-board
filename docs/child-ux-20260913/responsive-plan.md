# 반응형·밀도 계약 — 태블릿·크롬북·노트북 우선

기준 커밋 `601a8f0` · 근거 문서 `01_통합설계서.md` §3.2, `04_…기기최적화.md` §4·§5
측정 근거 `reports/audit-20260913/baseline/measurements.json` (176행, 5기기 × 기본·큰 글씨)

## 0. 왜 바꾸는가 — 측정으로 확인한 것

현재 토큰은 **손가락으로 휴대폰을 쓰는 아이** 기준이다(본문 20px, 조작 56px). 이 앱의
핵심 기기는 태블릿·크롬북·노트북이므로 그대로 두면 화면이 "세로로 늘린 휴대폰"이 된다.
`lib/childUx/tokens.ts` 는 이미 이 문제를 알고 **1024px 이상에서만** 한 단계 낮추는
override 를 하드코딩해 두었다(body 17px / control 44px). 측정으로 실제 작동을 확인했다.

문제는 그 처방이 세 가지 점에서 어긋난다는 것이다.

1. **값이 JSON 단일 소스 밖에 있다.** `tokens.json` 이 값의 유일한 출처라고 파일 주석이
   선언해 놓고, 넓은 화면 값만 `tokens.ts` 안에 리터럴로 박혀 있다. 검증 스크립트는
   JSON 만 읽으므로 이 값들은 아무 검사도 받지 않는다.
2. **경계가 화면 폭 하나다.** 1024px 태블릿 가로는 손가락으로 쓴다. 폭만으로 조작 영역을
   44px 로 줄이면 터치 기기에서 작아진다. 04 §4 가 "하이브리드 크롬북은 넓어도 터치
   가능하므로 hover/fine pointer 만 가정하지 않는다"고 못박은 지점이다.
3. **1024px 미만이 방치된다.** 820×1180 태블릿 세로와 800px 분할 화면은 override 를
   못 받아 본문 20px·조작 56px 그대로다. 사용자가 "글자가 너무 커서 UI 가 안 보인다"고
   한 화면이 바로 여기다(U02).

## 1. 밀도 계약 — 개정값

`01_통합설계서.md` §3.2 의 제안을 실제 토큰 값으로 확정한다. **역할별로 다르게** 내린다.
"넓은 화면이니까 전부 작게"도 "아이니까 전부 크게"도 아니다.

| 토큰 | 역할 | 기본(현재→개정) | 큰 글씨(현재→개정) |
|---|---|---|---|
| `body` | 게시글·댓글·일반 설명 | 20px → **16px** | 24px → **20px** |
| `body-emphasis` | 문제·짧은 안내 | 24px → **18px** | 28px → **22px** |
| `label` | 버튼·탭 | 18px → **15px** | 22px → **18px** |
| `secondary` | 이름·상태·보조 | 16px → **13.5px** | 18px → **16px** |
| `title` | 화면 제목 | 28~36px → **24~28px** | 34~43px → **30~34px** |
| `learn-sentence` **(신설)** | 학습 예문 | — → **18px** | — → **22px** |
| `learn-word` **(신설)** | 집중 학습 단어 1개 | — → **30px** | — → **38px** |
| `control-min` | 일반 조작 | 56px → **48px** | 64px → **56px** |
| `action-min` | 주 동작 | 64px → **56px** | 72px → **64px** |
| `control-gap-min` | 오터치 방지 간격 | 8px → **8px** (유지) | 8px → 8px |

**하한선은 낮추지 않는다.** 조작 영역 48px 은 WCAG 2.5.8 의 24px, 2.5.5 의 44px 를
모두 넘는다. `secondary` 13.5px 는 **필수 학습 지시에 쓰지 않는다**는 조건이 붙은
보조 크기다 — 이 규칙은 토큰 주석과 검사에 남긴다.

### 학습 역할을 일반 본문에서 분리하는 이유

사용자 요구는 "패들렛 글자가 너무 커서 UI 가 안 보인다"(U02)이지 "학습 글자를 줄여라"가
아니다. 게시글 본문 16px 과 학습 예문 18px·학습 단어 30px 을 **다른 토큰**으로 두면
게시판 밀도를 올리면서 단어 학습의 읽기 크기는 지킬 수 있다. 지금은 둘 다 `body` 라
한쪽을 고치면 다른 쪽이 깨진다.

## 2. 반응형 밀도 — 폭이 아니라 폭 + 입력 방식

화면 폭 하나로 판단하던 것을 **폭과 포인터 정밀도 둘 다** 보게 바꾼다.

```
글자 밀도   : 폭 기준        (960px 이상에서 한 단계 조밀하게)
조작 영역   : 포인터 기준     (coarse = 터치면 넓은 화면에서도 줄이지 않는다)
큰 글씨 선택: 두 축 모두 무시  (사용자가 크게 보려고 고른 설정을 화면이 되돌리지 않는다)
```

- 경계를 1024px → **960px** 로 내린다. 측정상 820px 태블릿 세로와 800px 분할이
  현재 밀도의 피해자이고, 960px 은 04 §5 의 "960~1199px = 학습/읽기 2영역 가능" 구간
  시작점과 일치한다.
- `@media (pointer: coarse)` 인 기기에서는 폭과 무관하게 `control-min` 48px,
  `action-min` 56px 을 유지한다. 1366px 터치 크롬북에서 버튼이 작아지지 않는다.
- 모든 값은 `tokens.json` 의 `responsive` 블록으로 옮긴다. `tokens.ts` 는 값을
  선언하지 않고 조립만 한다.

## 3. 컨테이너 폭별 배치 계약

04 §5 의 제안을 이 앱의 실제 콘텐츠에 맞춰 확정한다. 픽셀은 시작점이며 실제 라벨
길이와 큰 글씨에서 다시 확인한다.

| 컨테이너 폭 | 배치 |
|---|---|
| < 640px | 단일 주 영역, 보조 도구는 drawer/sheet |
| 640~959px | 콘텐츠별 2열, 상단 간결 내비, 보조 패널 접힘 |
| 960~1199px | 학습/읽기 2영역, 주요 목록 3열 |
| ≥ 1200px | 작업 영역 최대 폭 **1120~1280px**, 3~4열, 선택적 보조 패널 |

**2영역이 본문을 320px 이하로 만들면 더 넓은 폭에서도 1영역으로 되돌린다.**
글자를 줄여서 억지로 맞추지 않는다.

## 5. 이행 규칙 — 지키지 않으면 회귀한다

- **전역 zoom 축소로 밀도를 해결하지 않는다.** 현재의 `body zoom` + `data-ux-root`
  역보정 구조는 과도기 폴백이며, 화면을 토큰으로 이행할 때마다 `data-ux-root` 를 달아
  빠져나온다. `data-ux-root` 는 화면당 **정확히 하나** (중첩되면 배율이 두 번 되돌아간다).
- 새 전역 토큰 접두사를 만들지 않는다. 기존 `--ux-*` 를 확장한다.
- 화면마다 새 디자인 체계를 만들지 않는다. 기존
  `ChildButton`/`ChildCard`/`ChildText`/`TextSizeMenu`/`ScopedStyle` 을 재사용하고,
  없는 것만 `ActivityShell`/`AppIcon`/`Avatar`/`AnimalPicker`/`ReactionPicker`/
  `EmptyState`/`AsyncState`/`Modal` 로 추가한다.
- 하나의 거대한 CSS override 로 모든 화면을 강제하지 않는다. 화면별로 이행하고
  이행 경계를 `data-ux-root`/`data-ux-legacy` 로 명시한다.

- `node scripts/test-child-ux-tokens.mjs` — 대비·이중배율·JSON 단일소스 검사는 **유지**.

  **대비 검사와 hit area 검사를 지우는 방식으로 통과시키지 않는다.**

- 큰 글씨에서 어떤 역할도 기본보다 작아지지 않는지 자동 검사(기존 검사 유지).
- 브라우저 100/125/150/200% 확대와 큰 글씨를 **독립 설정**으로 시험.
