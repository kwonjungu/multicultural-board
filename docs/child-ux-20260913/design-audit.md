## 검증 한계 — 먼저 밝힘

- **실기기 없음.** 아래 모든 기기별 관찰은 Chrome headless의 **CSS viewport 시뮬레이션**이다.
  실제 태블릿 터치감·회전·브라우저 상단 UI 높이·크롬북 트랙패드는 확인하지 않았다 (04 §8 U09).
- **아동 사용성 테스트 없음.** 아래는 디자인 휴리스틱 검수이며 "아이들이 쉽게 이해했다"가 아니다.
- **fixture 로만 관찰.** 운영 방(1111)의 실제 학생 데이터는 쓰지 않았다.
- 측정 원본: `reports/audit-20260913/baseline/measurements.json` (176행) + PNG 352장.

## VOCAB-HOME — 단어 배우기 홈 (U07, 최우선)

**실제 진입 경로** 홈 → 단어 카드 / **역할** 학생 / **상태** 진도 0·진도 있음·표현 복습 있음
**viewport** 5기기 × 기본·큰 글씨 / **입력** 터치(태블릿·크롬북)·트랙패드(노트북)

**아이의 목표** — 오늘 배울 단어에 바로 들어가는 것. 이어서 하거나, 새 단원을 고르거나.

### 현재 보이는 구성과 증거

크롬북 1366×768 기본 글씨 첫 화면(`vocab-home__chromebook__basic__fold.png`) 위에서부터:

| 순서 | 요소 | 세로 점유 |
|---|---|---|
| 1 | 헤더 `📗 단어 카드` + `1/100 완료` + 뒤로 + 스티커 배지 | ~100px |
| 2 | HUD 3칸 — 하트 `5/5`, 연속 학습 `2`, `Lv.2 30/150` + `오늘 0/20 XP` | ~95px |
| 3 | **주황→핑크 그라디언트 배너** `오늘의 일일 챌린지 도전하기!` + `도전!` 리본 + `도전 →` | ~100px |
| 4 | `쓰기 학습지 만들기` 행 | ~60px |
| 5 | 단원 1 `인사와 만남` (초록) | 접힘선 위 마지막 |
| 6 | 레슨 노드 `1` (원형, 가운데) | |
| 7 | 단원 2 `내 마음과 감정` (주황) — 아래쪽 잘림 | |

측정값: **문서 높이 3565px, 첫 화면 비율 0.22** (큰 글씨 4451px / 0.17).
전체 조작 24개 중 첫 화면에 8개 이하. **`data-ux-role` 요소 0개** — body/label/secondary/title
computed font-size가 전부 `null` 이다.

### 불편

1. **첫 화면 355px(46%)이 학습이 아니라 상태 표시와 광고다.** 아이가 눌러야 할 단원 1은
   화면 절반 아래, 레슨 노드는 그보다 더 아래.
2. **진도 0인 첫 학생에게도 똑같은 화면이 나온다** (`vocab-home-new__chromebook__basic__fold.png`).
   `0/100 완료`, `연속 학습 0`, `Lv.0 0/50`, `오늘 0/20 XP`, 스티커 `0` — **0으로 채운 배지 6개**가
   먼저 나오고, 일일 챌린지 배너는 `소통판 단어 0개 + 약점 단어(틀린 단어) 0개` 라는
   **내용이 0개인 챌린지를 화면에서 가장 강한 색으로 광고한다.**
3. **폭이 545px 늘어도 콘텐츠는 20px 늘어난다.** 태블릿 세로 820px에서 콘텐츠 폭 ~780px,
   크롬북 1366px에서 ~760px. 좌우 300px씩은 배경 꽃밭. 5기기 캡처의 레이아웃이 사실상 동일 —
   **04 문서가 불합격이라고 못박은 "모바일 화면을 가로로 늘린" 구현이 그대로 재현된다.**
4. **레슨이 세로 1열 지그재그**라 3565px 페이지의 대부분을 만든다. 넓은 화면에서도 한 번에
   레슨 1~2개만 보인다.
5. **공통 토큰 밖에 있다.** `data-ux-role` 이 하나도 없어 '큰 글씨'가 토큰 경로로 먹지 않고
   legacy body zoom에만 의존한다. 보조 텍스트 `0/1 레슨 · ⭐ 0/3`는 큰 글씨에서도 작다.
6. **색이 화면마다 제각각.** 초록 단원1 / 주황 단원2 / 주황-핑크 챌린지 / 보라 `1/100 완료` /
   노랑 배지 / 빨강 하트. 크림·꿀빛 토큰과 무관하고, 색이 의미를 나르지 않는다.
7. 배경 일러스트가 카드 밖 전 영역을 덮어 읽기 배경으로 경쟁한다.

### 원인

정보 우선순위(상태·보상이 콘텐츠보다 위) · 배치(폭 확장 미대응, 1열 트리) ·
밀도(0 배지 과다) · 토큰 미이행(`data-ux-role` 부재).

### 수정 전 → 수정 후

- **HUD 3칸 → 접을 수 있는 한 줄 요약**으로 내리고, 진도 0이면 렌더하지 않는다.
- **일일 챌린지 배너 → 챌린지 대상이 1개 이상일 때만** 표시하고, 강조는 단원 카드보다 낮춘다.
  0개 챌린지는 어떤 형태로도 노출하지 않는다.
- **첫 화면 주인공을 `이어하기` 1개 + 단원/단어 행**으로 바꾼다. 진도가 없으면
  `이어하기` 대신 `단원 1부터 시작하기` 하나만 둔다 — 가짜 이어하기를 만들지 않는다.
- **레슨 트리를 폭에 따라 다열로**: 태블릿 세로 2~3열, 가로·크롬북 3~4열, 노트북 4열
  (04 §5 화면별 재배치). 목표는 720px 높이에서 단원 1개 + 레슨 행이 접힘선 위에 오는 것.
- `쓰기 학습지 만들기`는 교사/보조 기능이므로 학습 흐름 밖 보조 영역으로.
- 화면 전체를 `data-ux-root` + `data-ux-role` 로 이행하고 색을 꿀빛/크림 토큰으로 통일.
  단원 구분은 색만이 아니라 아이콘과 라벨로도 준다.

### 태블릿 세로 / 태블릿 가로 / 크롬북 / 노트북 차이

현재 **차이 없음**(위 3번). 목표: 세로는 단원 2열·요약 접힘, 가로/크롬북은 왼쪽 단원 목록 +
오른쪽 진행 요약 2영역, 노트북은 최대 폭 1120~1280px 안에서 4열.

### 유지할 기능

진도·하트·XP·연속 학습 데이터 계약, 레슨/단원 구성(`lib/lessons.ts`), 스티커 보상,
쓰기 학습지·받아쓰기·표현 복습 진입, 교사 보기.

### 우선순위

**D1** (04 §6 — "단어 배우기의 산만함, 기기별 재배치 부재"). 2번(0개 챌린지 광고)은 첫 학생의
첫인상을 망치므로 D1 안에서 먼저.

### 완료 기준

크롬북 1366×768 기본 글씨에서 **배너보다 실제 단어/단원 행이 먼저 보인다.**
진도 0 학생 화면에 0 배지와 0개 챌린지가 없다. 5기기 캡처에서 열 수가 실제로 달라진다.

## BOARD — 소통창(패들렛) (U02·U04·U06)

**진입** 입장 → 소통창 / **상태** 3주제, 50개 카드 칼럼 포함 / **입력** 터치·트랙패드

**아이의 목표** — 친구 글을 보고, 반응하고, 내 이야기를 올리는 것.

### 현재 보이는 구성과 증거

크롬북 1366×768(`board__chromebook__basic__fold.png`): 칼럼 3개 + `새 주제 추가` 점선 칼럼이
한 화면에 들어온다. 각 칼럼 = 색 헤더 + `Add here (여기에 추가)` + `주제 관리` + 카드.
카드 = 아바타 + 이름 + **`53시간 전`** + 언어 라벨 + 본문 + `Show original` + `Listen` + `Reply`.
하단 고정 CTA `Share my story (내 이야기 올리기)`.

측정값: **조작 개수가 1024px 경계에서 14개 → 318개로 뛴다.** 태블릿 세로는 칼럼 1개만,
크롬북/노트북은 전 칼럼을 그린다. 문서 높이 1109~1190px, 첫 화면 비율 0.69.
베트남어 본문 `p.pc-body` 글자 잘림이 1024px 이상에서만 재현.

### 불편

1. **U04 위반이 화면에 그대로.** `53시간 전`·`52시간 전`이 이름 바로 아래 눈에 띄는 자리.
2. **한 화면에 조작 318개.** 카드 50개 × (원문/듣기/답글/공감…). 04 §1 Q2 "가장 먼저 눌러야 할
   것이 다른 것과 경쟁하지 않는가"의 정반대.
3. **버튼 라벨이 전부 2개 국어 병기** — `Add here (여기에 추가)`, `Share my story (내 이야기 올리기)`,
   `See all topics (전체 주제 보기)`, `Leave (나가기)`. 라벨 길이가 두 배가 되어
   250px 칼럼에서 버튼이 2줄을 먹는다. 글을 천천히 읽는 아이에게 오히려 부담.
4. **카드 하나가 접힘선 안에 다 안 들어온다.** 768px 높이에서 첫 카드 본문이 잘리고
   `Listen`/`Reply`가 하단 고정 CTA에 눌린다.
5. 칼럼 헤더 아래 `Add here` + `주제 관리` 2줄이 카드보다 먼저 자리를 차지한다.
6. 베트남어 긴 본문 잘림 — `overflow-wrap`/`keep-all` 계약 미적용 의심.

### 원인

정보 우선순위(시간·관리 버튼이 작품보다 위) · 밀도(전 카드의 전 조작 상시 노출) ·
문구(불필요한 2개 국어 병기).

### 수정 전 → 수정 후

- **시간 문자열 제거** — `timestamp` 필드와 수정 가능 시간 판정은 그대로 두고 표시만 없앤다(U04).
- **카드 조작을 접는다** — 듣기/원문/답글/공감을 카드마다 상시 노출하지 않고,
  주 동작 1개 + 나머지는 펼침. 공감은 U06의 `ReactionPicker` disclosure로 통합.
- **버튼 라벨은 뷰어 언어 1개로.** 병기가 필요하면 보조 줄로 내리고 크기를 낮춘다.
- `주제 관리`는 교사 조작이므로 학생 화면에서 칼럼 헤더 밖으로.
- 카드 본문에 `overflow-wrap:anywhere` + 한국어 `word-break:keep-all` 적용.
- 태블릿 세로의 칼럼 선택 탭 방식과 보드 가로 스크롤 방식을 **둘 다 만들어 비교 후 선택**
  (04 §5). 의도한 보드 스크롤과 뜻하지 않은 문서 overflow를 구분한다.

### 우선순위

**D0** — 4번(카드가 접힘선 안에 안 들어오고 CTA에 눌림)은 핵심 읽기·행동 실패.
1번·3번은 **D1**.

### 완료 기준

첫 화면에 카드 1개가 본문·작성자·주 동작까지 온전히 들어온다. 시간 문자열이 없다.
정렬과 수정 가능 시간 경계는 이전과 같다.

## ENTRY — 입장 (U01·U05)

**진입** `/` → 방 번호 → 입장 / **상태** 1/2단계 언어 선택 / **입력** 터치·트랙패드

**아이의 목표** — 내 언어를 고르고 이름을 넣어 교실에 들어가는 것.

### 현재 보이는 구성과 증거

크롬북 1366×768(`entry__chromebook__basic__fold.png`): **화면 왼쪽 절반(약 610px)이 전부
장식**이다 — 꿀벌 3마리, 꿀단지, 꽃밭, 무지개 그라디언트 문구
`AI 꿀비와 함께하는 즐거운 소통 공간`. 콘텐츠는 오른쪽 565px 카드 안에만 있고,
언어가 2열로 10행 이상 이어져 스크롤이 생긴다.

측정값: 첫 화면 비율 0.63(큰 글씨 0.56). **첫 화면 장식 요소 20~23개 vs 조작 18개.**
보조폰 390px에서는 0.43 — 60%가 접힘 아래.

### 불편

1. **넓은 화면에서 늘어난 공간이 전부 장식에 간다.** 04 §1 Q5 위반. 1366px이면 언어를
   3~4열로 펼쳐 스크롤 없이 다 보여줄 수 있다.
2. 무지개 그라디언트 문구는 읽기 대비가 낮고 화면의 다른 어떤 텍스트와도 규칙이 다르다.
3. `1/2 단계` — U05 동물 선택이 들어가면 단계 수가 바뀐다. 지금 구조에 자리가 없다.

### 잘 되어 있는 것 (유지)

**언어 카드는 이 앱에서 가장 잘 된 컴포넌트다** — 그림 + 자국어 표기 + 그 언어의 인사말,
선택 시 굵은 갈색 테두리 + 체크(색 아닌 단서), 조작 크기 충분. **동물 선택(U05)은
이 카드 형태를 그대로 재사용한다** — 새 디자인 체계를 만들지 않는다.

### 수정 전 → 수정 후

- 좌측 장식 영역을 **폭에 따라 축소**하고 언어 그리드를 3~4열로. 장식은 배경으로 물린다.
- 그라디언트 문구를 단일 색 제목으로.
- 단계를 `언어 → 이름 → 내 동물` 3단계로 확장하되 **화면당 질문 하나** 규칙 유지,
  이전 선택은 보존하고 빠른 재입장 경로를 남긴다.

### 우선순위

**D1**(1번) / **D2**(3번, U05와 함께).

1366×768에서 언어 전체가 스크롤 없이 보인다. 동물 선택이 언어 카드와 같은 컴포넌트로

## 측정 도구의 한계 (정정 포함)

- `game` 화면에서 처음 보고된 **"44px 미만 조작 21건"은 제품 결함이 아니었다.**
  `ux-fixture/game` 자체의 게임 선택 칩이었다. 해당 nav에 `data-fixture-chrome` 를 달고
  측정 스크립트가 fixture 껍데기를 제외하도록 고쳤다.
- `board` 에서 1024px 이상일 때 `title` 이 16px로 측정된 것은 `querySelector` 가 잡은 첫
  `[data-ux-role="title"]` 이 화면 제목이 아니어서다. 화면 제목 크기의 결함으로 기록하지 않는다.
