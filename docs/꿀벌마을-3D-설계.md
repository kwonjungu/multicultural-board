# 🗺 꿀벌 마을 3D — 엔지니어링 설계서 (V3)

> 방향 확정(2026-07-13, 사용자): "꿀벌 마을 탭을 열면 **3D 맵**이 나오고,
> 동물의 숲처럼 **아이템을 모아 집을 꾸미는** 느낌. 문패·디자인 포함.
> 에셋은 대부분 디자인팀(나노바나나 배치)이 생성해서 넣는다."

## 1. 아키텍처 결정 (ADR)

### ADR-1. 렌더 스택 = three.js 바닐라 + 2.5D 아이소 스프라이트
- three.js 는 이미 의존성에 있음(MulticulturalGlobe). **react-three-fiber 등
  신규 의존성 금지.**
- 진짜 GLB 3D 모델 대신 **아이소메트릭 투명 PNG 스프라이트**를 3D 지형 위에
  빌보드/플레인으로 배치. 근거: ① 나노바나나 이미지 파이프라인(생성→검수→
  flood-fill 배경제거→트림) 그대로 재활용 ② 저사양 교실 태블릿 ③ 기존
  스티커 시리즈와 아트 톤 통일 ④ 에셋 1장 추가 = 파일 1개 (조합 폭발 없음).
- `components/VillageMap3D.tsx` 는 **next/dynamic + 클라이언트 전용 + 뷰포트
  진입 시 로드** (Globe 패턴). 메인 번들에 three.js 가 박히면 안 된다.

### ADR-2. 성능 예산 (교실 태블릿 기준)
- pixelRatio ≤ 1.5, 그림자 OFF, 안개/포스트프로세싱 없음.
- 스프라이트 ≤ 200 (학급 30명 × 집+마당 5~6개 + 공용 시설).
- 텍스처는 apply 단계에서 512px 로 다운사이즈. 카메라 정지 시 renderer 는
  invalidate-on-demand (연속 rAF 금지 — 배터리).
- WebGL 컨텍스트 생성 실패 시 **기존 2D hex 맵으로 폴백** (코드 삭제 금지).

### ADR-3. 카메라/조작
- 고정 아이소 앵글(약 35° 내려다봄) OrbitControls: 회전은 ±30° 제한,
  팬(드래그)·핀치 줌(0.7~2.0×)만. 터치 우선.
- 집/시설 탭 = raycast → 기존 집 상세 팝오버(2D DOM) 재사용. 3D 안에서
  DOM UI 를 다시 만들지 않는다 — **3D 는 무대, UI 는 DOM**.

### ADR-4. 데이터 모델 v2 (하위호환 필수)
```
village/{clientId}.house = {
  style: "hive" | "mushroom" | "tent" | "castle",   // 집 통짜 스프라이트
  plate: "wood" | "honey" | "flower",                // 문패 디자인 (이름은 캔버스 텍스처로 합성)
  fence: "wood" | "flower" | null,
  yard:  [itemId | null, itemId | null, itemId | null],  // 마당 슬롯 3
  // ↓ v1 필드 (roof/garden/plate 색) — 마이그레이션 매핑 후 유지(읽기 전용)
}
```
- v1 구매 이력(owned)은 그대로 유효. v1 `roof-*` 보유자는 대응 `style` 을
  무료 소유로 매핑 (🍄→mushroom, ⛺→tent, 🏰→castle, 기본→hive).
  v1 `garden-*` 은 대응 `yard` 꽃밭 아이템으로 매핑.
- 문패 텍스트 = 학생 이름. canvas 2D 로 문패 PNG 위에 이름을 그려 텍스처화
  (한글 폰트는 시스템 폰트, 텍스처 캐시 필수).

### ADR-5. 에셋 로딩 규약
- 경로: `public/village/<id>.png` (아래 매니페스트와 1:1).
- **모든 스프라이트는 로드 실패 시 색 박스(BoxGeometry) 폴백** — 디자인팀
  에셋이 아직 없어도 엔진이 먼저 배포 가능해야 한다 (2D 픽커의 이모지
  폴백과 같은 원칙).

## 3. 씬 구성 (엔진 스펙)

```
Scene
├─ ground: 평면 + ground-meadow 텍스처 (텍스처 없으면 연두 단색)
├─ plots[N]: 나선/격자 배치 (학생 수만큼, 결정적 순서 = 이름 정렬)
│   ├─ house 스프라이트 (style)
│   ├─ plate 스프라이트 + 이름 캔버스 텍스처 (집 앞)
│   ├─ fence (있으면 플롯 테두리)
│   ├─ yard[0..2] 스프라이트 (집 좌/우/앞 고정 오프셋)
│   └─ bee 빌보드: CharacterComposite 와 동일한 합성본 PNG 체인 —
│       stageImageWithSkinAndHat() 경로를 텍스처로 로드, 집 위에서 부유 애니
├─ center plot: 해금된 공동 시설 스프라이트 (fountain→clock→festival)
└─ ambient + directional light 1개씩 (그림자 없음)
```
- 탭(raycast) → `onSelectStudent(clientId)` 콜백 → BeeVillage 의 기존 팝오버.
- 내 집 편집: 팝오버(내 집)에 "🛋 꾸미기" → DOM 바텀시트(슬롯: 집/문패/울타리/
  마당×3) → 카탈로그에서 구매·장착 (owned/honey 로직은 기존 buyOrEquipDeco
  확장판 사용). 장착 즉시 3D 씬 갱신 (구독 에코).

## 4. 카탈로그 v2 (가격 — 꿀 경제 밸런스)

일일 수입 상한 ≈ 이슬 10 + 퀘스트 35~60 + 스티커 환전 → 주당 대략 300~400.
| 슬롯 | 아이템 | 가격 |
|---|---|---|
| 집 style | hive 기본 0 / mushroom 120 / tent 180 / castle 300 |
| 문패 plate | wood 기본 0 / honey 40 / flower 40 |
| 울타리 fence | wood 60 / flower 90 |
| 마당 yard | flowerbed-tulip 20 / flowerbed-rose 35 / bench 50 / mailbox 50 / lamp 60 / pond 80 / tree-cherry 100 / tree-honey 120 |
- v1 데코 소유자는 §1 ADR-4 매핑으로 손해 없음 (박탈 금지 원칙).

## 5. 실행 오케스트레이션

- **에이전트 C (엔진)**: VillageMap3D.tsx + BeeVillage 통합(3D 기본, WebGL
  실패 시 2D 폴백) + lib/village.ts 카탈로그 v2/마이그레이션. 에셋 없이도
  색 박스 폴백으로 완성해야 함.
- **에이전트 D (디자인팀)**: §2 매니페스트 21장 생성→검수→반영. GEMINI_API_KEY
  는 .env.local 에 있음. 하자 건은 배치 retry 경로로 재생성.
- C 와 D 는 병렬 (계약 = §2 파일명). 완료 후 오케스트레이터가 병합·e2e·배포.
